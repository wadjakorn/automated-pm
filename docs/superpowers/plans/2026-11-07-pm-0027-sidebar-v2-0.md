# PM-0027 Sidebar v2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the sidebar's ↑/↓ reorder operate on the rows the user can see, group hidden projects at the end with a persisted toggle, keep a hidden-but-selected project visible, and give Hide/Archive/Trash an Undo toast.

**Architecture:** All list arithmetic moves into a new pure module `components/sidebar-logic.ts` (unit-tested with vitest, node env). `components/Sidebar.tsx` keeps its structure (accordion menu, rail, mobile drawer) and only rewires `move`, `selectAfter`, the hidden toggle, and the three lifecycle actions to the pure functions and to the existing `toast(..., action)` API. No API, CLI, MCP, or schema changes.

**Tech Stack:** Next.js 15 / React 19 / Tailwind 3.4 / vitest 

**Spec:** `docs/superpowers/specs/2026-11-06-sidebar-topbar-v2-design.md` §3.0 (ticket PM-0027)

## Global Constraints

- No new components, no changes under `app/api`, `cli/`, `lib/mcp.ts`, `lib/repo.ts`.
- `sort_order` is never rewritten for display grouping; only an explicit move persists via `api.reorderProjects(ids)` with the FULL live id list.
- localStorage keys: existing `sidebar:open`; new `sidebar:show-hidden` ("1" | "0"); read after mount (no hydration mismatch), same pattern as `SIDEBAR_KEY`.
- Copy (exact): « title/aria `Collapse sidebar`; » `Expand sidebar`; toggle `Show hidden projects (n)` / `Hide hidden projects`; forced-open toggle title `Shown because the current project is hidden`; error toast `Couldn't <verb> "<name>". Try again.`; hide toast `Hidden "<x>"` + ` · Now showing <y>` when the selection moved; archive toast `Archived "<x>"`; trash toast `Moved "<x>" to Trash`; undo label `Undo`.
- Undo re-selects the project when it was the selected one at the time of the action.
- Keep `window.confirm` on delete (replaced in PM-0018).

## Review Focus

1. Move within the hidden group while "show hidden" is on must not reorder visible projects, and vice-versa → Task 1 test "hidden group move leaves visible order untouched".
2. ↑ on the first shown row of a group and ↓ on the last must be disabled even when hidden rows sit before/after them in the full order → Task 1 tests "up at first shown returns null" / "down at last shown returns null"; Task 2 wires `disabled` from group index.
3. A hidden project opened by URL must render an active row, and the toggle must not look clickable while it is forced open → Task 2 (`forced` → toggle disabled + title).
4. Undo after hiding the selected project must restore both `hidden=false` and the selection → Task 2 (capture `wasSelected` before the call).
5. Archiving or trashing the selected project must pick the nearest shown neighbour (not the first row) and the board must never sit on a removed project → Task 1 `neighbourAfterRemoval` tests; Task 2 calls `selectAfter` in `archive` and `del` (today only `setHidden` does).

### Task 1: Pure sidebar logic

**Files:**
- Create: `components/sidebar-logic.ts`
- Test: `components/sidebar-logic.test.ts`

**Interfaces:**
- Consumes: `Project` from `@/lib/types` (fields `id`, `hidden`).
- Produces:
  - `orderForDisplay(projects: Project[], showHidden: boolean): Project[]` — visible projects in input order, then (only if `showHidden`) hidden projects in input order.
  - `moveVisible(fullIds: string[], groupIds: string[], id: string, to: -1 | 1 | "top" | "bottom"): string[] | null` — `groupIds` is the display group the project belongs to (visible ids, or hidden ids, each in full-order sequence). Returns the new FULL order, or `null` when the move is a no-op (id missing from either list, or already at the group edge). Ids outside the group keep their relative positions: remove `id` from `fullIds`, then insert it immediately before the anchor for `-1`/`"top"` (anchor = previous group member / first group member) or immediately after the anchor for `1`/`"bottom"` (anchor = next group member / last group member).
  - `neighbourAfterRemoval(shownIds: string[], removedId: string): string | null` — the id at `index - 1`, else `index + 1`, else `null` (also `null` when `removedId` is not in the list).
  - `actionFailed(verb: string, name: string): string` — exactly `` `Couldn't ${verb} "${name}". Try again.` ``.

- [ ] **Step 1: Write the failing tests**

```ts
// components/sidebar-logic.test.ts
import { describe, expect, it } from "vitest";
import type { Project } from "@/lib/types";
import { actionFailed, moveVisible, neighbourAfterRemoval, orderForDisplay } from "./sidebar-logic";

function project(id: string, hidden = false): Project {
  return { id, name: id, description: null, remote_repo_url: null, default_status_key: null,
    ready_status_key: null, theme_pack: null, theme_accent: null, ticket_prefix: null,
    sort_order: 0, hidden, created_at: "", updated_at: "", deleted_at: null, archived_at: null };
}

describe("orderForDisplay", () => {
  const list = [project("h1", true), project("a"), project("h2", true), project("b")];
  it("drops hidden projects when the toggle is off", () => {
    expect(orderForDisplay(list, false).map((p) => p.id)).toEqual(["a", "b"]);
  });
  it("appends hidden projects after visible ones, each group in input order", () => {
    expect(orderForDisplay(list, true).map((p) => p.id)).toEqual(["a", "b", "h1", "h2"]);
  });
});

describe("moveVisible", () => {
  const full = ["h1", "a", "h2", "b", "c"];
  const visible = ["a", "b", "c"];
  it("moves up past a hidden neighbour, keeping the hidden one in place", () => {
    expect(moveVisible(full, visible, "b", -1)).toEqual(["h1", "b", "a", "h2", "c"]);
  });
  it("moves down past a hidden neighbour", () => {
    expect(moveVisible(full, visible, "a", 1)).toEqual(["h1", "h2", "b", "a", "c"]);
  });
  it("returns null at the first shown row even when a hidden row precedes it", () => {
    expect(moveVisible(full, visible, "a", -1)).toBeNull();
  });
  it("returns null at the last shown row", () => {
    expect(moveVisible(full, visible, "c", 1)).toBeNull();
  });
  it("moves to top before the first group member", () => {
    expect(moveVisible(full, visible, "c", "top")).toEqual(["h1", "c", "a", "h2", "b"]);
  });
  it("moves to bottom after the last group member", () => {
    expect(moveVisible(full, visible, "a", "bottom")).toEqual(["h1", "h2", "b", "c", "a"]);
  });
  it("hidden group move leaves visible order untouched", () => {
    expect(moveVisible(["a", "h1", "b", "h2"], ["h1", "h2"], "h2", -1)).toEqual(["a", "h2", "h1", "b"]);
  });
  it("returns null for an id outside the group or the full list", () => {
    expect(moveVisible(full, visible, "h1", 1)).toBeNull();
    expect(moveVisible(full, visible, "zzz", 1)).toBeNull();
  });
  it("does not mutate its inputs", () => {
    const f = full.slice(); const g = visible.slice();
    moveVisible(f, g, "b", -1);
    expect(f).toEqual(full); expect(g).toEqual(visible);
  });
});

describe("neighbourAfterRemoval", () => {
  it("prefers the previous row", () => expect(neighbourAfterRemoval(["a", "b", "c"], "b")).toBe("a"));
  it("falls back to the next row at the top", () => expect(neighbourAfterRemoval(["a", "b", "c"], "a")).toBe("b"));
  it("returns null when nothing else is shown", () => expect(neighbourAfterRemoval(["a"], "a")).toBeNull());
  it("returns null for an unknown id", () => expect(neighbourAfterRemoval(["a", "b"], "x")).toBeNull());
});

describe("actionFailed", () => {
  it("formats a readable sentence", () => {
    expect(actionFailed("hide", "capz")).toBe('Couldn\'t hide "capz". Try again.');
  });
});
```

```ts
const selectedIsHidden = projects.some((p) => p.id === selectedId && p.hidden);
const forced = selectedIsHidden;               // auto-reveal, not persisted
const shown = orderForDisplay(projects, showHidden || forced);
const fullIds = projects.map((p) => p.id);
const visibleIds = projects.filter((p) => !p.hidden).map((p) => p.id);
const hiddenIds = projects.filter((p) => p.hidden).map((p) => p.id);
const shownIds = shown.map((p) => p.id);

Remove the old `visible` constant; render `shown` where `visible` was rendered. `hiddenCount` stays.

- [ ] **Step 2: Rewire `move`, `reorder`, `selectAfter`**

```ts
async function reorder(ids: string[]): Promise<void>            // persists ids, then onProjectsChanged(); error → toast(actionFailed("reorder", "projects"), "error")
function move(p: Project, to: -1 | 1): void                     // groupIds = p.hidden ? hiddenIds : visibleIds; next = moveVisible(fullIds, groupIds, p.id, to); if next → reorder(next)
function selectAfter(removedId: string): Project | null         // if removedId !== selectedId → null; nextId = neighbourAfterRemoval(shownIds, removedId); onSelect(nextId) when found; return the Project (for toast copy)
```

In the row menu compute `const groupIds = p.hidden ? hiddenIds : visibleIds; const gi = groupIds.indexOf(p.id);` and set `disabled={gi <= 0}` on ↑ and `disabled={gi >= groupIds.length - 1}` on ↓ (replacing `fullIdx`).

- [ ] **Step 3: Undo toasts for hide / archive / trash**

Each handler: `const wasSelected = p.id === selectedId;` before the API call; on success `setMenuFor(null); const next = selectAfter(p.id); onProjectsChanged();` then

```ts
toast(`Hidden "${p.name}"${next ? ` · Now showing ${next.name}` : ""}`, "success", {
  label: "Undo",
  onClick: async () => {
    try { await api.updateProject(p.id, { hidden: false }); onProjectsChanged(); if (wasSelected) onSelect(p.id); }

Replace every `toast(e.message ?? ..., "error")` with `toast(actionFailed(<verb>, p.name), "error")` using verbs `hide` / `show` / `archive` / `move` (trash) / `reorder`.
